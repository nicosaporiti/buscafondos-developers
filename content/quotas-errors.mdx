# Cuotas y errores

Cada key puede tener una cuota diaria que se reinicia a medianoche en `America/Santiago`. Además, la política pública limita tráfico por IP a 10 requests por segundo, con ráfagas de hasta 20.

## Headers de cuota

| Header | Significado |
| --- | --- |
| `X-RateLimit-Limit` | Cuota diaria asignada a la key. |
| `X-RateLimit-Remaining` | Requests disponibles después de la llamada. |
| `X-RateLimit-Reset` | Timestamp Unix del próximo reinicio. |
| `Retry-After` | Segundos que conviene esperar; aparece en `429` y algunos `503`. |

Los headers se exponen por CORS, por lo que clientes de navegador pueden leerlos.

## Comportamiento HTTP real

- `401 Unauthorized`: falta la key, es inválida o fue revocada. Incluye `WWW-Authenticate: Bearer`.
- `403 Forbidden`: **no forma parte del flujo de API key de los endpoints de datos**. Actualmente aparece en superficies de cuenta cuando el origen no es confiable; no lo uses para inferir cuota.
- `429 Too Many Requests`: cuota diaria agotada o exceso de tasa. Cuando se agota la cuota incluye los cuatro headers anteriores.
- `5xx`: falla transitoria o datos actualizándose. La validación de keys y algunos resúmenes pueden responder `503` con `Retry-After: 5`.

<Callout title="Fuente de verdad">El OpenAPI actual no enumera globalmente todas estas respuestas del middleware. Este comportamiento fue confirmado en `app/apikeys.py` y `app/main.py`; la referencia generada conserva exactamente lo que declara OpenAPI.</Callout>

## Retry con backoff y jitter

<CodeExample title="TypeScript" language="typescript" code={`async function requestWithRetry(url: string, apiKey: string) {
  for (let attempt = 0; attempt < 4; attempt += 1) {
    const response = await fetch(url, {
      headers: { "X-Api-Key": apiKey },
    });

    if (response.ok || ![429, 500, 502, 503, 504].includes(response.status)) {
      return response;
    }

    const retryAfterHeader = response.headers.get("Retry-After");
    const retryAfterSeconds =
      retryAfterHeader === null || retryAfterHeader.trim() === ""
        ? Number.NaN
        : Number(retryAfterHeader);
    const fallbackMs = 500 * 2 ** attempt + Math.random() * 250;
    const waitMs = Number.isFinite(retryAfterSeconds) && retryAfterSeconds >= 0
      ? retryAfterSeconds * 1000
      : fallbackMs;

    await new Promise((resolve) => setTimeout(resolve, waitMs));
  }

  throw new Error("BuscaFondos no respondió después de 4 intentos");
}`} />

No reintentes `401` ni `403`. Corrige autenticación o permisos primero. Lee la [política de uso completa](https://api.buscafondos.com/policy) antes de automatizar cargas grandes.
